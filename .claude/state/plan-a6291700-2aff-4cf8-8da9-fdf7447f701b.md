# Plan: release notes written by the local Claude CLI before a push (owner request, 2026-11-07)

## What changes
- `scripts/release-notes/generate.mjs`: add `callClaudeCli` (runs `claude -p --json-schema ... --tools "" --setting-sources user --no-session-persistence`) and a `local` option / `--local` flag so the generator works without `ANTHROPIC_API_KEY`. The API path used by `.github/workflows/release-notes.yml` stays as it is.
- New `scripts/release-notes/claude-pre-push-hook.mjs`: a Claude Code PreToolUse hook. When the Bash command is a `git push` that sends `main`, it runs the generator locally and commits `apps/web/src/content/release-notes.json` with the `[skip release-notes]` marker, so the entry goes out in the same push. It never blocks the push (always exits 0) and skips when the notes file has local edits.
- New `.claude/settings.json` (project, committed) registering that hook for the Bash tool.

## Rules it is near
- Loop prevention for release notes (DECISIONS "Release notes"): the bot commit carries `[skip release-notes]`, which the generator already drops, and the nested `claude -p` loads only user settings, so it cannot re-enter this project hook.
- `.claude/` guard (z-harness): this only adds a hook; it does not change or weaken any existing gate (no harness.json edits).
- Secrets: nothing new is stored; the local CLI uses the developer's own login.

## Verification

- Pipe a fake PreToolUse payload (`{"tool_input":{"command":"git status"}}`) into the hook: exits 0 doing nothing; with `git push` on main and new commits: writes + commits an entry (checked with `git log -1`).
