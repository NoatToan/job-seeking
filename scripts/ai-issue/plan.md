## Your task: write an implementation plan (no code changes)

Read the code the request touches and write a plan a maintainer can approve or correct:

- **Understanding**: the request in two or three sentences, and what is out of scope.
- **Approach**: the change, file by file (paths), including data model / API / UI changes.
- **Steps**: small steps, each mergeable on its own.
- **Tests**: what you will test and how.
- **Open questions**: anything the maintainer must decide, numbered so they can answer "1: ...".

If the issue already has an earlier plan and maintainer comments, write a new plan that takes
those comments into account.

Do not edit any file. Your final message is posted as-is as a comment on the issue: Markdown, no
headings above `###`, at most about 60 lines.
